# Search compatibility: YDB 25.1–26.3

Choose documentation with `?version=v25.1`, `v25.2`, `v25.3`, `v25.4`, `v26.1`, `v26.2`, or `v26.3`, matching the target server. Read the feature page and the release notes together: a documented feature may still be disabled by default. Keep the selector when following links. Unversioned URLs do not establish compatibility with a particular release, and `version=main` describes development documentation.

Check the exact server build where a row below names a patch or release candidate. Server and SDK versions are independent; upgrading an SDK does not enable a server feature. The notes below concern row-oriented tables.

## Release guide

Exact search using the `Knn` functions is documented throughout this range. The 25.1–26.1 documentation indexes contain vector search, but do not establish a released full-text or native `HybridRank` contract. Select vector/exact examples for those releases unless an extension has been verified on the target.

| Server release | Documented search behavior | Consequence for the examples |
|---|---|---|
| **25.1** | Vector indexes and inference of parameter types are listed in **25.1.2.7 RC**. The vector pages warn that an index does not track later table changes. [Release notes](https://ydb.tech/docs/en/changelog-server.md?version=v25.1#25-1-2-7-rc), [vector guide](https://ydb.tech/docs/en/dev/vector-indexes.md?version=v25.1). | Verify vector-index availability and the exact build. Load data before building; do not promise indexed-write support or fresh ANN results after writes. Use explicit parameter declarations when inference is unavailable. |
| **25.2** | Vector indexes are enabled by default in **25.2.1.10 RC**. The guide describes assigning updates to existing clusters, but the DDL/SELECT pages retain older no-update warnings. [Release notes](https://ydb.tech/docs/en/changelog-server.md?version=v25.2#25-2-1-10-rc), [guide](https://ydb.tech/docs/en/dev/vector-indexes.md?version=v25.2#update), [DDL](https://ydb.tech/docs/en/yql/reference/syntax/create_table/vector_index.md?version=v25.2). | Keep the load-then-build path. Verify update behavior on the actual build before using ANN over changing data; the documentation disagreement does not identify a reliable patch boundary. |
| **25.3** | Vector updates are documented as assignments to fixed clusters; substantial data changes can degrade recall. **25.3.1.27** fixes an `ALTER TABLE` failure on tables with a vector index. [Guide](https://ydb.tech/docs/en/dev/vector-indexes.md?version=v25.3#update), [release notes](https://ydb.tech/docs/en/changelog-server.md?version=v25.3#25-3-1-27). | SQL writes do not retrain the cluster tree. Monitor recall and rebuild when needed; use a patched build for affected schema operations. |
| **25.4** | **25.4.1.15** documents `overlap_clusters`, a fix for inserted rows with previously unseen vector-filter values, and vector execution improvements. [Release notes](https://ydb.tech/docs/en/changelog-server.md?version=v25.4#25-4-1-15). | Check the patch when a filtered ANN index misses newly added categories. Treat overlap as a tuning option, not a requirement for the shared three-dimensional example. |
| **26.1** | Vector indexing and fixed-cluster updates continue; **26.1.1.22** fixes a crash while updating a vector index. [Guide](https://ydb.tech/docs/en/dev/vector-indexes.md?version=v26.1#update), [release notes](https://ydb.tech/docs/en/changelog-server.md?version=v26.1#26-1-1-22). | For changing indexed data, check the patch level. Do not infer full-text or native hybrid support from newer documentation. |
| **26.2** | `fulltext_plain` and `fulltext_relevance` are documented, and full-text indexes are enabled by default in **26.2.1.14**. The guide requires a **single `Uint64` primary key**. [Release notes](https://ydb.tech/docs/en/changelog-server.md?version=v26.2#26-2-1-14), [full-text limitations](https://ydb.tech/docs/en/dev/fulltext-indexes.md?version=v26.2#limitations). | The shared `documents` schema fits. Use vector and standalone full-text queries. For combined retrieval, fuse their rankings in the application; do not emit native `HybridRank` as a supported 26.2 query. |
| **26.3** | **26.3.1.16 RC** adds native hybrid search, full-text filter columns, and arbitrary full-text primary-key types under **Disabled functionality**. They are not enabled by default in that release candidate. [Release notes](https://ydb.tech/docs/en/changelog-server.md?version=v26.3#26-3-1-16-rc). | Verify enablement before using `hybrid-search.sql`, filtered full-text indexes, or automatic document IDs. A page describing the feature is not evidence that it is enabled on the cluster. |

## Limits that need a release-specific answer

- **Writes after vector-index creation:** the 25.1 guide says table changes are not reflected in an existing index, while its DDL page also warns against mutations. The 25.2 guide and syntax pages disagree about update support. For these targets, verify supported mutations and ANN freshness rather than assuming the later maintenance behavior. An unindexed table with exact search or a validated rebuild/replacement workflow can serve changing data. [25.1 DDL](https://ydb.tech/docs/en/yql/reference/syntax/create_table/vector_index.md?version=v25.1), [25.2 SELECT](https://ydb.tech/docs/en/yql/reference/syntax/select/vector_index.md?version=v25.2).
- **Vector tuning and encodings:** keep the shared `float` index, explicit type/dimension, and explicit `KMeansTreeSearchTopSize` as the baseline. Older parameter lists are inconsistent about `overlap_clusters`; the 25.4.1.15 notes explicitly describe it. The 25.1/25.2 pages warn against bit indexes, and the release DDL pages through 26.3 do not document half-precision index types. Do not infer portable index support from the existence of a `Knn` conversion UDF, or categorically reject a type independently verified on the target. [25.1 DDL](https://ydb.tech/docs/en/yql/reference/syntax/create_table/vector_index.md?version=v25.1), [25.2 DDL](https://ydb.tech/docs/en/yql/reference/syntax/create_table/vector_index.md?version=v25.2), [26.3 DDL](https://ydb.tech/docs/en/yql/reference/syntax/create_table/vector_index.md?version=v26.3).
- **Full-text schema:** keep a single `Uint64` key for the portable 26.2 example. The 26.3 guide describes broader integer keys and automatic `__ydb_row_id`/`__ydb_unique_row_id` support for other keys, but the release notes list arbitrary-key support and full-text filter columns as default-disabled features. Verify them before changing the schema. [26.2 limitations](https://ydb.tech/docs/en/dev/fulltext-indexes.md?version=v26.2#limitations), [26.3 key types](https://ydb.tech/docs/en/dev/fulltext-indexes.md?version=v26.3#primary-key).
- **Full-text query terms:** `Or` and `MinimumShouldMatch` are documented in 26.2. The required `+term` behavior within `Keywords`/`Or`, counting only optional terms, is explicit in the 26.3 docs. Do not infer that this later description establishes identical behavior on an earlier target. The bundled query adds no `+` prefixes. [26.2 functions](https://ydb.tech/docs/en/yql/reference/builtins/fulltext.md?version=v26.2), [26.3 functions](https://ydb.tech/docs/en/yql/reference/builtins/fulltext.md?version=v26.3).
- **Native hybrid prefixes:** the 26.3 guide and syntax reference explicitly exclude prefixed vector indexes. Use the shared non-prefixed `vec_idx` for documented 26.3 hybrid queries. Standalone filtered vector search does not establish filtered-index support inside `HybridRank`; an extension needs independent target verification. [26.3 hybrid limitations](https://ydb.tech/docs/en/dev/hybrid-search.md?version=v26.3#limitations), [26.3 syntax](https://ydb.tech/docs/en/yql/reference/syntax/select/hybrid_search.md?version=v26.3#limitations).

## Select the bundled SQL and SDK path

| Target | Files and modes to use |
|---|---|
| 25.1–26.1 | `create-table.sql`, initial `upsert.sql`, `exact-search.sql`, and the vector index/search files after confirming availability. Skip full-text index creation and the `fulltext`/`hybrid` calls. Apply the early-release write caveats above. |
| 26.2 with full-text support | Add `add-fulltext-index.sql` and `fulltext-search.sql`. If combining lexical and semantic results, retrieve both candidate lists and fuse by document ID in the application, using ranks rather than an uncalibrated sum of raw scores. |
| 26.3 with native hybrid enabled | The complete shared walkthrough, including `hybrid-search.sql`. It uses non-prefixed indexes and a single `Uint64` key, so it does not require the additional filtered/full-text arbitrary-key features. |

The shared files omit `DECLARE` because SDK requests supply typed values. The release notes introduce that ability in **25.1.2.7 RC**; confirm type inference is enabled, or add declarations from the [SDK parameter contract](sdk.md#parameter-contract). Do not duplicate declarations generated by an SDK. `String` embedding parameters remain the recommended representation in every path; version checks do not justify switching to `List<Float>`.

A documented release capability can still be disabled by cluster configuration. Verify the required capability without proposing an automatic configuration change. If the exact build is unknown, state the example's minimum documented requirements instead of assuming the complete hybrid walkthrough applies.
